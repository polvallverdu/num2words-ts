# Porting conventions

Rules for porting num2words (Python, pinned in `.upstream/num2words`, see `upstream.json`) to
TypeScript. The goal is **identical output** to upstream for every input: same words, same
exceptions. `test/parity.test.ts` checks this against a corpus generated by running the real Python
library (`bun run fixtures`), and the upstream test suite is ported 1:1 next to it.

Reference files, hand-ported first: `src/py.ts` (Python semantics), `src/base.ts`,
`src/currency.ts`, `src/lang/EU.ts`, `src/lang/EN.ts`. Copy their patterns.

## Files and names

| Python | TypeScript |
|---|---|
| `num2words/lang_XX.py` | `src/lang/XX.ts` (same code, e.g. `src/lang/PT_BR.ts`) |
| `num2words/base.py`, `currency.py`, `utils.py`, `compat.py` | `src/<same>.ts` |
| `tests/test_xx.py` | `test/test_xx.test.ts` |
| `class Num2Word_XX` | `class Num2Word_XX` (unchanged) |
| methods / attributes `to_cardinal`, `negword` | `toCardinal`, `negword` (camelCase) |
| `_private` | `_private` (camelCase, keep the underscore) |
| constants `GENERIC_DOLLARS` | unchanged |
| keyword arguments (`gender='f'`, `longval=False`) | options object `{ gender: "f", longval: false }` (camelCase keys) |

`num2words()` passes its options to the converter method as one object, so every `to_*` method
takes `(value, options = {})` and destructures what it uses, with upstream's defaults (`??`).

## Header (license)

Copy **every** `Copyright` line of the upstream file verbatim, then ours, then the SPDX line and
the source path. `bun run lint` checks the notices against the upstream file.

```ts
// Copyright (c) 2003, Taro Ogawa.  All Rights Reserved.

```

Test files use the same header with `tests/test_xx.py`.

## Numbers (most important)

Python has three number types and upstream relies on the differences. Inside the library:

| Python | TypeScript |
|---|---|
| `int` (unbounded) | `bigint` — literals `10n`, `1000n` |
| `float` | `number` — a `number` is **always** a float |
| `Decimal` | `Decimal` from `src/py.ts` |
| `isinstance(x, int)` | `typeof x === "bigint"` |
| `isinstance(x, float)` | `typeof x === "number"` |
| `isinstance(x, Decimal)` | `x instanceof Decimal` |
| `a // b`, `a % b`, `divmod(a, b)` on ints | `floordiv(a, b)`, `mod(a, b)`, `divmod(a, b)` — **never** `/` or `%` on bigints with possible negative operands (JS truncates, Python floors) |
| `int(x)`, `float(x)`, `abs(x)`, `round(x)`, `str(x)` | same-named helpers in `py.ts` (`str(1e16)` is `"1e+16"`, `round` is banker's) |
| `x == y`, `x < y` across types | `eq(x, y)`, `cmp(x, y) < 0` |
| `"%02d" % n` | `zeroPad(n, 2)` |
| `10 ** n` | `10n ** BigInt(n)` |
| `str(n)` for an int | `n.toString()` |
| `len(str(n))` | `n.toString().length` (abs first if negative, as upstream does) |

A value whose type upstream checks (`to_currency`, `to_cardinal`) is typed `PyNum`
(`bigint | number | Decimal`). After upstream's own integral check, convert with `int(value)`
and work in bigints.

## Python idioms

| Python | TypeScript |
|---|---|
| dict lookup that can raise `KeyError` | `getItem(d, k)` (throws `KeyError`) |
| list index that can raise `IndexError` / negative index | `at(seq, i)` |
| `for a, b in zip(x, y)` | `for (const [a, b] of zip(x, y))` |
| `range(a, b, step)` | `range(a, b, step)` (numbers) or a plain `for` loop |
| `OrderedDict` | `Map` (insertion order) |
| `"sep".join(xs)` | `xs.join("sep")` |
| `s.split()` (no arg) | `s.split(/\s+/).filter(Boolean)` |
| `s.strip()` | `s.trim()` |
| `s[-1]`, `s[:-1]` | `s.slice(-1)`, `s.slice(0, -1)` |
| `"%s %s" % (a, b)` | template literal, with `str(x)` for numbers |
| `raise NotImplementedError(...)` etc. | `throw new NotImplementedError(...)` from `py.ts`; `TypeError` is JavaScript's |
| `except (A, B):` | `catch (e) { if (!(e instanceof A || e instanceof B)) throw e; ... }` |

Exceptions must match upstream's class *names* exactly; the parity corpus compares them.

## Classes (important JavaScript pitfall)

`Num2Word_Base`'s constructor calls `setup()`, and upstream assigns most fields there. In
JavaScript, a subclass's field declarations run *after* the base constructor and would reset them.
So in converter classes:

- **Never** write plain field declarations or initializers. Declare fields assigned in `setup()` or
  methods with `declare name: Type;` (type-only, emits nothing).
- Python **class attributes** (`CURRENCY_FORMS = {...}`, `GIGA_SUFFIX = ...`) become `static`
  members, read through `this.cls.X` (or `(this.constructor as typeof Num2Word_XX).X` for ones the
  base class doesn't declare), so subclass overrides work like Python's `self.X`.
- Overrides keep the base method's parameters; extra Python keyword arguments go in the options
  object.

## Tests

- Port each upstream test file 1:1 with `bun:test`. `class TestX(TestCase)` → `describe("TestX")`,
  `def test_y` → `test("test_y")`. Keep every assertion and its expected string.
- `num2words(1.0, lang="ru")` → `num2words(asFloat(1), { lang: "ru" })`: integral floats must use
  `asFloat` (JavaScript cannot tell `1` from `1.0`). Non-integral literals (`1.5`) are already
  floats. `Decimal('1.5')` → `new Decimal("1.5")`. Big ints → `bigint` literals.
- `assertRaises(E)` → `expect(() => ...).toThrow(E)`.
- A test that cannot pass because of a real behavioral difference: `test.skip` with a
  `// DIVERGENCE:` comment explaining it. Never weaken an assertion.

## Checks

`bun test`, `bun run typecheck`, `bun run lint`. `bun tools/parity.ts <lang>` prints the corpus
mismatches for one language while porting it.
